E10. Data Preprocessing, class distribution bullet (add at end)

Your notes ask whether the data is balanced. This sentence answers it and explains why PRC area is also reported.

The classes are moderately imbalanced: the majority class (Medium) is twice the size of the smallest class (Low), and a classifier that always predicts Medium would already be 46.0% accurate. We therefore report kappa, per-class TP and FP rates, and precision-recall (PRC) area alongside accuracy and ROC area, since ROC area alone can look optimistic when classes are imbalanced. No resampling was applied. The PR thresholds were chosen before any modelling, and no instance has a PR of exactly 0.7 or 0.8.

E18. Attribute Selection, add pros and cons under each method

Your comment asks for pros and cons. Paste each sentence after that method's description.

Gain Ratio: Dividing by intrinsic information removes information gain's bias toward attributes with many values. However, it can over-reward attributes with very few distinct values, such as rare-event indicators like flood. It also scores each attribute on its own, so redundant attributes can all be selected.

CFS [9]: It looks for a subset of attributes that are each correlated with the class but not with each other, so it removes redundancy automatically and chooses the subset size itself. However, its best-first search is greedy and may miss attributes that are only useful in combination.

Information Gain: It is fast and easy to interpret, but it favours attributes with many distinct values. Like the other rankers, it ignores redundancy, and the number of attributes to keep must be chosen by hand (we used 10).

Correlation: It is fast and simple, but Pearson correlation only measures linear relationships, so non-linear effects such as seasonal patterns can be under-ranked. It also ignores redundancy between attributes.

Manual selection: It uses domain knowledge and keeps attributes with a clear physical link to PR. However, it depends on our judgement and could miss useful attributes we did not expect to matter. We excluded season (covered by month), snow_value_mm (overlaps with total_daily_snow_mm), the ticket, hurricane, storm, flood and lightning attributes (the same value on about 99% of days), and nearest_hurricane, nearest_storm and nearest_flood (these fall back to days since commissioning when no event occurred, so they mostly repeat plant age).

E21. Naive Bayes description

The last sentence is cut off.

One weakness is that it treats each attribute independently by generating probability values
Naive Bayes [8] is a classifier that uses Bayes' theorem to compute a probability for each class label (Low, Medium and High) and predicts the class with the highest probability. It assumes that all attributes are independent given the class, and Weka models each numeric attribute with a normal distribution. It is very fast and works well with little data. However, when attributes are strongly related, as month and season or the three snow attributes are here, the same evidence is counted several times and the probabilities become distorted.

E22. J48 description

Adds the citation and corrects the splitting criterion wording.

J48 constructs a tree that splits data by the attributes that separates class labels(low, medium, high) by info gain ratio.
J48 is Weka's implementation of the C4.5 decision tree [5]. It builds a tree by repeatedly splitting the data on the attribute with the highest gain ratio.

E23. Random Forest description

Adds the citation.

Random Forest consists of many decision trees which are trained across different samples and subsets of attributes.

E24. JRip description

The description of the default rule is the key point. It explains why JRip over-predicts Medium in the results.

JRip is a classifier that builds a set of if-then statements. JRip starts from the least common class labels ... a more common label.
JRip is Weka's implementation of the RIPPER rule learner [7]. It learns an ordered list of if-then rules, starting with the least frequent class (Low), then High. Any instance that matches no rule is assigned the most frequent class (Medium) by a final default rule. The rules are easy to read and prune well. However, instances that match no rule all fall into the majority class, which can lower recall for the smaller classes.

Results and Evaluation

Evaluation setup

Each of the 5 attribute sets (Manual, Information Gain, Correlation, CFS and Gain Ratio) was used to train each of the 4 classifiers (J48, Random Forest, JRip and Naive Bayes), giving 20 models. All models were built in the Weka Explorer [3] with default parameters: J48 -C 0.25 -M 2; RandomForest -P 100 -I 100 -num-slots 1 -K 0 -M 1.0 -V 0.001 -S 1; JRip -F 3 -N 2.0 -O 2 -S 1; NaiveBayes with no options.

Every model was evaluated in two ways. First, it was trained on the full training set (34,877 instances) and tested on the held-out test set (8,720 instances) using Weka's "Supplied test set" option. Second, it was evaluated with stratified 10-fold cross-validation on the training set only. Test-set results are the primary results reported below; cross-validation results are used to check that the ranking is stable.

The test set contains 4,012 Medium (46.0%), 2,020 Low (23.2%) and 2,688 High (30.8%) instances. A classifier that always predicts the majority class (Medium) would therefore reach 46.0% accuracy, which we use as the baseline.

Selection of the best model

We selected Random Forest trained on the Manual attribute set as our best model. On the held-out test set it reaches 72.51% accuracy and a kappa of 0.569, compared with the 46.0% majority-class baseline. We chose it for four reasons.

  1. It is the best model on almost every overall measure. Among all 20 models it has the highest test accuracy (72.51%), kappa (0.569), weighted F-measure (0.725), MCC (0.568), weighted ROC area (0.877) and weighted PRC area. It also has the lowest RMSE (0.3559).
  2. It is the best at identifying Low-PR days. Its TP rate for Low (0.663) is the highest of all 20 models, and its FP rate for Low (0.091) is the lowest among the four best models. Low PR is the class that points to an underperforming plant, so missing Low days and raising false Low alarms are the two most costly errors.
  3. It ranks instances best. Its ROC area is 0.889 for Low and 0.890 for High. A high ROC area means its class probabilities are reliable, so a user could raise or lower the threshold for flagging Low days to trade missed days against false alarms.
  4. Its result is stable. Its 10-fold cross-validation accuracy (73.43%) is within 1 point of its test accuracy (72.51%), so the result does not depend on one lucky split.

The next two models, Manual + J48 (72.35%) and Information Gain + J48 (72.29%), are within 0.25 points in accuracy, and under cross-validation Information Gain + J48 is slightly ahead (73.50% vs. 73.43%). Accuracy alone therefore does not separate the top three. We preferred Random Forest because its ROC area is clearly higher (0.877 vs. 0.839 and 0.852). J48 could be preferred for its readability, but its trees here have 2,189 leaves (Manual) and 1,596 leaves (Information Gain), so in practice they are not much easier to interpret than a forest.

Discussion

The choice of classifier mattered about twice as much as the choice of attributes. Averaged over the five attribute sets, test accuracy ranged from 69.24% for J48 and 68.72% for Random Forest down to 62.32% for JRip and 55.63% for Naive Bayes, a spread of 13.6 points. Averaged over the four classifiers, the attribute sets ranged from 66.87% (Information Gain) to 60.40% (Gain Ratio), a spread of 6.5 points. The ordering of the classifiers was the same for every attribute set except that Random Forest beat J48 on the Manual and Gain Ratio sets.

The two tree-based classifiers were clearly the strongest. J48 and Random Forest occupy the top 8 places, with test accuracy between 64.70% and 72.51% for every attribute set. They can split on combinations of attributes (for example, climate region and month together) without assuming any distribution, which suits this data where the relationship between weather, location and PR is not linear.

The top of the ranking is a near tie between the Manual and Information Gain sets. The four best models (Manual and Information Gain, each with J48 and Random Forest) are all between 71.94% and 72.51% on the test set. Our manual set, chosen from domain knowledge before seeing any model results, performed as well as the best automatic method. The two sets share 8 attributes: NOAAClimRegion, TempZone, month, plant_age_months, low_irradiation, total_daily_snow_mm, cumulative_snow_mm and nearest_rain.

plant_age_months appears to be the most important single attribute. The three attribute sets that include plant_age_months (Information Gain, Manual and Correlation) are the top three by mean accuracy. The two that exclude it (CFS and Gain Ratio) are the bottom two, and with J48 and Random Forest they are 2 to 8 points less accurate. Plant age reflects panel degradation, but combined with climate region it may also identify individual sites. Because our train/test split is random over days, days from the same site appear in both sets, so part of this gain may come from the model recognising sites it has already seen. Results on completely new sites would likely be lower.

Gain Ratio produced the weakest attribute set. It was the worst set with all four classifiers. Gain Ratio favours attributes with few distinct values, so it ranked rare-event attributes such as flood and duration_minutes_flood highly. These have the same value on almost every day and carry little information, and they pushed plant_age_months out of the top 10. CFS kept only 8 attributes yet still came fourth, ahead of Gain Ratio, which shows that the choice of attributes mattered more than their number.

Models below 60% accuracy, and why they are low. Six models score below 60%: all five Naive Bayes models (52.80% to 57.61%) and Gain Ratio + JRip (58.54%). All of them still beat the 46.0% baseline, but they are not usable. Naive Bayes assumes attributes are independent given the class, which is strongly violated here: month and season, the three snow measures, and TempZone and NOAAClimRegion are closely related, so the same evidence is counted several times. It also models each numeric attribute as a normal distribution, while snow and rain are zero on most days with a long tail. JRip learns rules for the smaller classes (Low, then High) and assigns everything else to the majority class, Medium, through its default rule. Both behaviours show in the confusion matrices: Gain Ratio + Naive Bayes predicts Medium for 69.9% of actual High days and 55.4% of actual Low days, and its TP rate for Low is only 0.144. We addressed the low performance by comparing five attribute sets and four classifiers. Changing classifier from Naive Bayes or JRip to a tree-based method raised accuracy by 6 to 16 points on every attribute set, and our best model reaches 72.51%.

Most remaining errors are between neighbouring classes. In the best model, 80% of the 2,397 misclassified test days involve the Medium class, and only 469 (20%) are Low days predicted as High or the reverse. The classes are ranges of one continuous value (Low below 0.7, Medium 0.7 to 0.8, High above 0.8), so a day with PR of 0.79 and one with 0.81 are almost identical but fall in different classes. Medium is also the narrowest range. Some error near the boundaries is therefore unavoidable with these attributes. Other causes of low PR, such as inverter faults, soiling and shading, are not recorded in the data, which limits the accuracy any model can reach.

Cross-validation and test results agree. For every model, test accuracy is within 2.9 points of its 10-fold cross-validation accuracy (mean difference 0.8 points, largest for Gain Ratio + JRip). The best four models are the same under both evaluations, only in a slightly different order. The models are therefore not overfitting the training data, and the comparison does not depend on the particular test split.

Conclusion

We built and compared 20 classification models that predict the daily performance-ratio class (Low, Medium or High) of PV plants from site, weather and time attributes. The best model, Random Forest with our manually selected 12 attributes, classifies 72.51% of held-out days correctly (kappa 0.569, weighted ROC area 0.877), compared with 46.0% for always predicting the majority class. It also has the best TP rate for Low-PR days (0.663), the class that matters most for spotting underperformance. Information Gain with J48 or Random Forest performs almost as well, which confirms that the result does not depend on one particular attribute set.

What we learned.

  • The choice of classifier had a larger effect than the choice of attribute selection method. Comparing all 20 models, rather than only the winner, made this clear.
  • Domain knowledge was as effective as the best automatic attribute selection. Our manual set matched Information Gain, while Gain Ratio was misled by rare-event attributes. Automatic methods should be checked against an understanding of the data, not accepted as they are.
  • Accuracy alone can hide important differences. Models with similar accuracy differed in ROC area and in how well they found Low days, and the weak models reached their accuracy mostly by predicting Medium. Per-class TP and FP rates and the confusion matrices were needed to see this.
  • All preprocessing that learns from data (imputation, standardisation and attribute selection) must be fitted on the training set only. We did this throughout, and the close agreement between cross-validation and test results suggests the evaluation is sound.
  • How the data is split affects what the results mean. Our random split lets the same site appear in both training and test sets. A split by site would give a better estimate of performance on new plants and is the main improvement we would make in future work, along with trying class boundaries based on PR quantiles and adding attributes such as irradiance and maintenance records.
